# 架构维护、发布与实际部署

通用改动的公开仓库为 https://github.com/BrianChen33/personal-ai-companion-kit 。每次改善程序、协议或部署说明，都要发布并核实真实远端 commit；本机保存、生成安装包和口头宣布均不算已同步。

## 文档职责

- README：系统构成、近期变化、给 Agent 的入口提示词，保留两大部分。
- DEPLOY_FOR_BOT：唯一详细安装顺序；CURRENT_RULES：共同运行约定；CAPABILITIES：交付范围与宿主条件。
- 模块文档/插件 PROTOCOL：该模块具体规则与格式。按任务阅读，避免复制成多个不一致版本。
- CHANGELOG：简短历史概况；releases/provenance：发布证据；legacy/superpowers：旧接口与研发记录。它们不进入默认运行提示词。
- 更新现有段落，不向 AGENTS、部署与继承入口不断追加“当前某版本”说明。撤销过时执行规则时保留个人历史和仍有效的数据格式。

## 发布一个版本

1. 检查本次范围与工作树，保留六层、原数据和明确授权。公开内容只包含通用实现、规范和合成样例，不含真实人格、记忆、渠道身份、私有角色素材或凭据。
2. 更新包版本、provenance、当前说明与 release manifest。只改文档时明确 runtime/插件/前端均未变，旧固定发布清单不重写。
3. 一次最终隔离验收：现有 test_all 与 wheel 检查；文档另查链接、版本与协议冲突。不为低影响文字编写镜像测试，不向生产发送队列或真实账本放探针。失败只做相关修正。
4. 正常发布，独立读取远端分支 commit；网络或权限受限时报告实际阻碍，不搬运其他环境凭据。

## 部署是单独的事实

**公开版本更新不等于线上 Agent 已升级。** 用户本轮只要求公开代码/文档时，报告公共版本和实际部署范围，不改正在运行的 Muse、任务或私库架构锁。

当本轮包含实际部署时，读回目标宿主代码、配置、入口和任务，确认真实安装 commit；再更新该宿主私库 README、LATEST、manifest 的架构锁并核实远端快照。只部署了一部分时如实记录组件版本，不能用新公共 commit 掩盖旧运行代码。私人授权与部署资料不写入公共来源记录。

日常情绪、日记、关系与生活变化走既定私库备份，不每轮提交代码。部署失败或未执行就保留实际旧锁，不能为“版本一致”伪造升级。最终报告公开版本、实际启用版本、完成范围、限制与后续工作。
