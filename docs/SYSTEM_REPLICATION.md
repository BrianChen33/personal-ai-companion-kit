# 如何在另一个个人 AI 助理里复刻

复刻的是六层运行机制以及用户选择的人格/数据，不能仅复制一份 SOUL 就声称系统已部署。完整安装顺序只有 [DEPLOY_FOR_BOT](../DEPLOY_FOR_BOT.md) 一份；这里是跨平台复刻的边界说明。

## 哪些能复用，哪些需要接线

| 可直接复用 | 目标平台需要提供或适配 |
|---|---|
| Python 核心、SQLite 数据格式、检索与状态算法 | 持久私有磁盘、运行权限、可信身份和消息来源 |
| 情绪/生活结构和同模型评估协议 | 当前回复模型按返回格式提交变化；不新增独立情绪模型 |
| 连续生活、过程、作品和来源区分 | 后台执行、调度、实际阅读和主动联系能力 |
| 通用表达/表情策略 | 用户人格、合法素材、媒体发送与真实回执 |
| 原格式私库快照与插件数据协议 | 账户授权、实际存储/导出、恢复后重新绑定 |
| 面板模板和 3D 前端 | 私有页面、状态接口、角色模型与设备能力 |

新 Agent 先从 [能力目录](CAPABILITIES.md) 列出可装范围，再按用户选择处理。四个独立插件之外的模块仍可能需要手工宿主接线；记账只有适配与结构蓝图，没有原网页完整源码。

## 一轮消息和后台

当前主聊流程由 [FAST_REPLY](FAST_REPLY.md) 定义：context → 同一模型评估 → commit → 正文/媒体 → 真实 finish。底层兼容接口与其他渠道遵循自己的返回 schema，不混用旧的重复准备流程。

持续心情与本轮反应分开；角色可以合作但不必自动开心。未来计划、虚拟体验、梦境和真实观察分别保存。主动输出不重复刺激情绪；后台和主聊共用已有事件、分享与回执机制。

普通聊天不读取所有文档或插件，后台不因为迁移就重放旧任务。模型能够返回正确 JSON，不代表宿主已接到每轮消息；安装者必须分别说明代码、接线与实际结果。

## 复刻完成的证据

用空白私有状态和合成样例做一次有界验收；核对实际安装版本、人格/状态位置、插件选择和真实宿主绑定。没有正式发送拦截、原生后台或公开工具的地方明确标记缺口。平台名称出现在 README，不是该平台已通过整套安装的证明。

需要继承时阅读 [INHERITANCE](INHERITANCE.md)。已安装/已接线/已观察到真实结果分别报告。第二个平台的完整空白安装仍是后续工作，当前不承诺任意平台开箱即用。
