# 六层核心与可选插件：分阶段路线

状态：**项目所有者已同意按阶段推进，每完成一块先停下汇报。** Kit 0.15.1 完成第一块：安装入口、当前规则、能力目录与历史说明分离。Kit 0.16.0 完成第二块：Muse 消息抽离、通用主人单聊文字入口及合成示例。其余模块拆分、安装自动化及第二个真实平台验收尚未完成。本文件是研发路线，不是安装 Agent 获得的重构授权。

## 保留一个小核心

六层是伙伴如何工作的共同流程；插件是伙伴可以选择具备的具体能力。核心应能独立完成有记忆、有情绪、有日常的普通聊天，不把六层拆成六个互相等待的服务。

| 核心层 | 保留的基本职责 | 可以挂接的插件 |
|---|---|---|
| 输入层 | 统一事件、身份与来源范围、去重、时间 | QQ、微信、邮件、健康、短信等输入适配 |
| 记忆层 | 原话/事件、事实、人物关系、时间检索、摘要与生命周期 | 可选向量检索提供方、GitHub 私库交付 |
| 情绪层 | 同一模型评估、混合情绪、衰减、精力、联系欲望、未解期待 | 插件提交有来源的观察；不能直接乱改情绪 |
| 生活层 | 自己的虚拟生活状态、连续事件、计划与已发生的区别 | 阅读与成长、生活相机、丰富日程内容包 |
| 表达层 | 人格、简短表达、当前反应与背景心情、真实投递回执 | 表情包、梗知识与串子、语音、图片 |
| 反馈与观测 | 幂等、失败状态、轻量检查、备份协议、插件健康状态 | 离线面板、3D 小屋、不同备份目的地 |

人格底稿及成长后的个性属于核心。具体平台接线、工具页面和领域数据属于插件。记账中心、用户行程安排室、招聘管理等应用使用自己的结构化数据；不把全部流水/岗位/日程挤进核心记忆。需要聊天时只提供相关摘要。用户日程与伙伴自己的虚拟日程始终分开。

## 分组让新 Agent 询问安装

首次先建立或继承人格，再一次性展示可选能力：

- 聊天渠道：QQ、微信、其他受支持渠道。
- 生活与表达：阅读成长、生活相机、表情包、梗知识。
- 个人工具：记账中心、睡眠运动、邮件、用户行程/招聘应用。
- 查看与迁移：轻量面板、3D 小屋、GitHub 私有备份。

用户可回答“只装核心”“核心加记账和相机”或逐项选择。默认不装任何可选插件。Agent 只追问所选插件真正缺少的条件：账本币种/钱包、阅读许可链接、相机参考图、账户授权、私库目标。已有明确偏好不重复询问。不因已有记忆就自动扩大权限。

插件目录必须标明 `available`、`experimental`、`planned`。当前实际独立插件是阅读成长、生活相机、健康及本次新增记账适配；QQ/微信/面板等已有实现仍需按计划抽离，视频、邮件等未完成能力不能包装成一键可用。

## 保持回复速度

不引入多服务、消息总线或新的每轮模型。插件注册表只保存轻量元数据。

1. 普通聊天只读核心紧凑上下文。
2. 有关请求才加载对应插件；禁用插件不执行、不查网络。
3. 生活触发与观察在既有后台节奏运行，不让所有插件每轮巡检。
4. 页面只在打开时读取所需数据；大表分页，图片/模型按需缓存。
5. 数据库保留清晰所有权。插件把相关观察交给核心，核心回传表达/分享决定，避免各插件再造情绪和人格。

## 同一份数据，分别保存代码与私人状态

公开 Kit 保存安装器、插件版本、空表结构、界面和测试样例。私库保存核心原格式记忆以及用户允许的插件配置和数据。

每个插件声明：数据所在处、格式与 schema 版本、导出方式、大小上限、备份范围和恢复步骤。现有 `brain.sqlite` 中的插件表随核心数据库一次备份，不重复复制；空间数据库通过只读导出产生备份时刻快照，绝不把快照当第二套运行数据库。可重建缓存默认省略。凭据、登录态和既有明确排除的原始健康数据不因“插件化”被自动纳入。

继承流程：读取清单 → 按锁定版本安装所选插件 → 导入数据到新停用目标 → 核对条数、余额与关联 → 重新绑定宿主和权限 → 用户选择后启用。未安装插件的数据保留但不执行；旧任务与旧交易不重放。

## 分步实施建议

第一步整理当前文档和能力目录，把版本历史移到变更记录，让 Agent 先读短的当前规则。第二步先建立宿主消息适配边界，保留 Muse 旧入口；通用协议只接已认证主人的私密文字单聊。第三步逐组抽离表情包/梗库/小屋与渠道能力，再统一安装问答和插件备份清单。最后再把用户行程、招聘等独立应用做成可选插件。

每步只迁移一组明确职责，沿用正在工作的真实数据与任务。无需为“模块化”改写整套数据库或同时切换所有插件。每个插件只有在真实能力、费用边界和一次针对性验收明确后，才能标成可安装。
