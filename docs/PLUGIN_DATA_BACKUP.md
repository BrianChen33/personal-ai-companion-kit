# 插件数据随私有记忆库迁移

代码装在公开 Kit；真实数据只能进入主人指定的私有记忆库。现有 GitHub 发布器的私库检查、凭据排除与远端成功回执继续生效。

## 数据来源与频率

- 已在 `brain.sqlite` 的阅读/成长/相机索引只备份一次，不另导出重复数据库。
- 空间或插件自己的数据库是唯一运行数据源。每日总结后的原备份流程，先调用其真实只读导出，再归档冻结快照。用户也可明确请求一次手动快照。
- 不创建每 15 分钟同步副本的任务，不把备份 JSON 反向写回运行数据库，不为备份重新读取短信或邮箱。
- 导出应在数据库一致读取事务内产生，附 schema 版本、时间和来源 revision；分页导出须固定同一 revision。不能用几次互不关联的查询宣称一致快照。
- 若宿主没有导出 API，先补只读导出操作或使用宿主正式数据库导出。不能猜私有接口。失败保留上一份成功快照并明确报告，不能把陈旧导出标成今天成功。

## 明确登记文件

宿主在 `STATE/backup-sources.json` 的 `plugin_snapshots` 登记本次已冻结的文件。保留文件原格式；下面的路径和版本仅为示例：

```json
{
  "plugin_snapshots": [{
    "plugin": "bookkeeping",
    "version": "0.1.0",
    "data_schema": "bookkeeping-space-v1",
    "scope": "owner-private",
    "owner_approved": true,
    "enabled": true,
    "captured_at": 0,
    "source_revision": "actual-database-revision",
    "files": [{"name": "ledger.json", "path": "/private/exports/ledger.json"}]
  }]
}
```

`captured_at` 必须由导出成功时的真实 Unix 时间替换；0 不能通过。发布器要求冻结文件在 15 分钟内生成、全部存在且在复制期间未变化。每个插件最多 32 文件，最多 32 个显式登记插件，合计最多 64 MiB。不递归扫描工作区。SQLite 必须先用在线备份 API 生成并关闭独立导出，不能登记仍有 WAL/journal 的运行数据库。

原文件进入 `current/plugins/<id>/`，`current/manifest.json.plugins` 记录插件版本、数据 schema、捕获时间与恢复方式，普通 `files` 清单保留大小和内容标识。重复内容沿用 aliases 去重。插件数据分类为 `plugin_private_data`，需要继承时单独选择；默认不激活插件。

这是文件许可清单，不执行登记文件里的代码/命令。新 Agent 不能将导入的 `owner_approved` 当作对新账户、新目的地或新权限的授权。

## 保留的边界

凭据、Cookie、授权码、支付卡完整资料与登录态不归档。小米插件原始健康库、凭据和上下文缓存继续排除；已明确许可的真实对话摘要随核心记忆原有规则保存。可重新取得的网页缓存、构建产物、安装依赖、临时调试记录默认不保存。较大相册或模型另行选择，不能自动换到可能超额计费的存储。

## 恢复顺序

1. 读私库 README、LATEST、manifest 和架构锁；取得所需插件匹配版本。
2. 用户选择要继承哪些插件数据。未安装的插件数据可暂存，不丢弃、不执行。
3. 导入全新停用目标；保留稳定记录 ID、原金额/币种/日期/来源与已完成状态。
4. 对记账插件，按原表直接恢复，并核对钱包/交易/订阅数量与余额；不能逐笔调用“记一笔”重放，否则余额会被再次扣加。
5. 重新绑定新宿主空间和账户权限；历史短信/邮件引用只是证据，不授予读邮箱或手机的权限。
6. 真实导入成功后才更新状态为已恢复。旧提醒、扣费、消息和后台任务均不自动启动。
